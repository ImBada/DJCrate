# 구조 개선 계획 — TDD 기반 마련과 리팩터링 (2026-09-26)

목표: rekordbox를 깨뜨리지 않는다는 원칙을 **테스트로 강제**하고, 한 파일에 몰린 책임을 나눠 새 기능(곡 직접 추가·코멘트 자동 채우기·파형 생성 등)을 안전하게 얹을 수 있게 한다. 동작은 바꾸지 않는 리팩터링이고, 단계마다 배포 가능한 상태를 유지한다.

## 1. 지금 상태 (측정값)

| 항목 | 값 |
|---|---|
| 전체 | Swift 16,259줄, 타깃 4개(AnicueCore, AnicueApp, anicue CLI, AnicueCoreTests) |
| 단위 테스트 | 83개, 코어 줄 커버리지 **29.9%**, 앱 타깃 0% |
| 큰 파일 | DeckModel 1,676 · main.swift 1,426 · DeckView 992 · RekordboxWriter 899 · DeckAudio 847 · ContentView 653 |

**가장 위험한 코드에 테스트가 없다**
- rekordbox 쓰기의 핵심 커버리지: `RekordboxWriter` 0.6%, `RekordboxGridWriter`·`AnlzFile`·`SeekInfo`·`Timeline`·`CipherDatabase` 0%.
- 지금까지는 rekordbox 실험 → 사본 재현(`loop-repro` 등) → 앱 자가 테스트로 검증했다. 믿을 만하지만 반복하기 무겁고, 리팩터링의 안전망이 되지 못한다.
- 분석(`KeyAnalyzer`, `MemoryCueSuggester`, `Waveform`, `Onset`)도 0%.

**책임이 한곳에 몰려 있다**
- `DeckModel`(@MainActor, 1,676줄) 한 클래스에 12가지가 들어 있다:
  - 게인·조성 흐름·곡 로드와 다시 읽기·재생·루프
  - CDJ식 CUE·큐 편집(15개 함수)·그리드 편집(15개)·그리드 제안
  - 알림·설정 저장(UserDefaults 직접)·파일 입출력(`DeckPayload`·`DraftWriter`·`ArtworkCache`·`Thumbnails`)
  - 앱 자가 테스트 6개
- 순수 규칙이 앱 타깃 안에 있어 단위 테스트를 못 한다. 예:
  - 핫큐 누름·루프 걸기·나가기·½×2·즉석 루프 저장
  - 메모리 큐 한도, 그리드 따라 핫큐 옮기기, 게인 제안
  - 목록 필터(`LibraryFilter`·`TrackRow`), 반영 대상 고르기
- `DeckAudio`(847줄)에 엔진 연결·디코딩·루프 예약·클릭·미터·진단이 섞여 있다. 이번에 `PlaybackSchedule`을 코어로 뺀 게 첫걸음이다.
- `RekordboxWriter`(899줄)에 계산(무엇을 쓸지)과 실행(DB 입출력)·백업·검증이 한 함수 흐름에 섞여 있다.
- `ContentView`(653줄)에 반영 흐름(미리 보기 → 확인 창 → 쓰기 → 토스트)이 `NSAlert`와 함께 있다.
- `main.swift`(1,426줄)에 명령 44개가 한 파일에 있고, 그중 상당수가 끝난 실험용이다(probe·dump·diff·repro).

**전역 의존이 테스트를 막는다**
- 환경 변수 직접 읽기 14곳.
- 정적 경로: `AnicuePaths`·`LibrarySnapshot.rekordboxDirectory`·`RekordboxShare.directory`.
- `isRekordboxRunning()`이 pgrep를 부른다. `UserDefaults`를 직접 쓴다. `.shared` 싱글턴이 2개 있다.

## 2. 목표 구조

의존 방향은 한쪽으로만 흐르게 하고, SwiftPM 타깃으로 강제한다(위가 아래를 모름).

```
AnicueApp (SwiftUI·AppKit 화면, 앱 진입점)
   └─▶ AnicueFeatures (@Observable 화면 모델·조정자: Deck, Library, Reflection — 가짜로 테스트 가능)
         ├─▶ AnicueAudio (AVAudioEngine 덱: 재생·루프 예약·클릭·미터 — 오프라인 렌더로 테스트)
         ├─▶ AnicueAnalysis (파형·그리드 추정·조성·음량·섹션·캐시)
         ├─▶ RekordboxKit (SQLCipher DB·ANLZ 읽기/쓰기, 쓰기 계획/실행, 백업, 스냅샷, 버전 검사)
         └─▶ AnicueDomain (순수 Swift: 모델·초안·편집 규칙·루프 규칙·그리드 따라가기·PlaybackSchedule·코멘트 규칙·필터·표시 문자열)
anicue CLI ─▶ RekordboxKit, AnicueAnalysis, AnicueDomain   (lab 하위 명령은 실험용)
```

원칙은 "순수한 속, 얇은 겉"이다.
- **규칙**은 `AnicueDomain`에서 값 타입 함수로 둔다. 입력 → 출력만 있고 입출력·시계·싱글턴이 없다.
- **부수 효과**는 경계 프로토콜 뒤로 보낸다:
  - `DeckAudioEngine`(재생), `Clock`(시각), `DraftRepository`(초안 저장), `SettingsStore`(설정)
  - `ProcessInspector`(rekordbox 실행 여부), `RekordboxLocation`(경로)
- 앱 시작점(`AnicueApp`) 한 곳에서만 실제 구현과 환경 변수를 엮는다.
- 화면 모델(`DeckModel` 등)은 규칙과 경계를 조립만 한다. 목표는 파일당 400줄 이하.

## 3. TDD 기반 (0단계 — 모든 리팩터링의 안전망)

1. **테스트 재료 만들기**(`Tests/Support`)
   - `RekordboxFixture`: 실제 master.db에서 뽑은 **스키마(CREATE 문)만**으로 같은 키의 암호화 DB를 만들고 곡·큐·contentCue·agentRegistry(인증값 없이)·contentFile·djmdMixerParam을 넣는 빌더. 실데이터·토큰은 커밋하지 않는다.
   - `AnlzBuilder`: PMAI/PQTZ/PQT2/PWAV 등 작은 합성 분석 파일.
   - `AudioFixture`: 램프·무음·사인 WAV·AAC(AVAudioFile로 생성), 필요하면 수 KB짜리 무음 MP3·FLAC 고정 파일.
   - `OfflineRenderHarness`: AVAudioEngine 수동 렌더링. 루프 이음새·클릭을 장치 없이 결정적으로 검사한다(오늘 쓴 오프라인 실험을 테스트로 옮김).
2. **특성 테스트(지금 동작 고정)** — 위험 순서대로
   - **rekordbox 쓰기 골든 테스트**: 실험 결과(Flip Flop·ときめき 루프 행, つよがる 244→245 BPM 행, じもとっこ 이동 바이트, 流れ行く命 게인, FLAC SeekInfo)를 합성 픽스처 위의 기대값으로 옮긴다. 막힘 조건도 하나씩 테스트한다: rekordbox 실행 중(가짜 `ProcessInspector`), 초안 base 불일치, 메모리 큐 10개 초과, 활성 루프 2개, 파형 없는 곡 그리드, VBR MP3.
   - **ANLZ**: 인코드/디코드 왕복, 그리드 밖 태그 바이트 보존, 내림·−1ms 규칙, PQT2 소수 → +0.5ms 규칙.
   - **Timeline·SeekInfo**: 합성 파일 헤더로 지연 계산·FLAC 프레임 위치.
   - **분석**: 키 추정·섹션 → 메모리 큐 제안을 합성 신호로 최소 검증(회귀 방지 수준).
3. **작업 규칙**(`AGENTS.md`에 추가)
   - 새 규칙·버그 수정은 실패하는 테스트부터 쓴다(red → green → refactor). 오늘 메트로놈 수정이 예시다.
   - rekordbox 쓰기 규칙을 새로 알아내면 실험 곡 이름·날짜와 함께 골든 테스트를 추가한다.
   - 단위 테스트는 실제 라이브러리·음원·장치를 쓰지 않는다(빠르고 결정적으로). 실물 확인은 앱 자가 테스트가 맡는다.
4. **검사 스크립트** `scripts/check.sh`
   - `swift build` + `swift test` + 커버리지 요약 + (선택) 주요 자가 테스트.
   - CI는 macOS 27 SDK가 필요해 당장은 로컬 스크립트와 pre-commit 훅으로 대신한다.

0단계 완료 기준: rekordbox 쓰기 관련 파일 커버리지 80% 이상, 코어 전체 60% 이상, 모든 기존 자가 테스트 통과.

## 4. 단계별 계획

동작을 바꾸지 않는 리팩터링이다. 단계마다 브랜치 하나(`refactor/…`), 끝나면 `swift test` + 자가 테스트 + 앱 설치 확인 후 dev에 합친다.

| 단계 | 내용 | 완료 기준 | 규모 |
|---|---|---|---|
| 0 | TDD 기반(위 3절) | 쓰기 커버리지 ≥ 80% | 큼 |
| 1 | **타깃 나누기**: AnicueCore → AnicueDomain / RekordboxKit / AnicueAnalysis. 앱에 있는 순수 규칙(TrackRow·LibraryFilter·표시 문자열·게인 제안 계산)을 Domain으로 | 앱 → 코어 방향만 남음, 테스트 그대로 통과 | 중간 |
| 2 | **DeckModel 분해**(아래) | DeckModel ≤ 400줄, 덱 규칙 단위 테스트, carry·loop 자가 테스트를 단위 테스트로 대체 | 큼 |
| 3 | **DeckAudio 정리**: AnicueAudio 타깃, `DeckAudioEngine` 프로토콜, 루프 전환 계획(바퀴 경계·늘이기·줄이기·나가기)을 순수 함수로 → 오프라인 렌더 테스트 | 루프·클릭 테스트가 장치 없이 돎 | 중간 |
| 4 | **RekordboxWriter 분리**: `WritePlanner`(현재 행 + 초안 → 쓸 행·JSON, 순수) / `WriteExecutor`(트랜잭션·검증) / `BackupStore` / `WriteGuard`(실행 중·버전·스키마 검사). 경로·프로세스 확인은 주입 | 골든 테스트가 계획 단계만으로도 돎 | 중간 |
| 5 | **화면·흐름 정리**: DeckView(21개 뷰)·ContentView를 파일별로, `ReflectionCoordinator`(미리 보기 → 확인 → 쓰기 → 토스트, 확인 창은 프로토콜), LibraryStore를 목록 읽기·필터·초안 색인으로 | 반영 흐름 단위 테스트, 파일당 ≤ 400줄 | 중간 |
| 6 | **CLI 정리**: 명령별 파일, 끝난 실험 명령은 `anicue lab …`으로 옮기거나 지움, RegexConventionParser 등 옛 비교 코드 제거 | main.swift ≤ 150줄 | 작음 |
| 7 | **자가 테스트·진단 격리**: DevSelfTests·PerfProbe·DeckModel 안의 자가 테스트 6개를 `#if DEBUG` 전용 파일로, 단위 테스트로 대체된 것은 삭제 | 릴리스 빌드에 진단 코드 없음 | 작음 |

### 2단계 — DeckModel 분해 상세

| 새 단위 | 위치 | 맡는 것 | 테스트 |
|---|---|---|---|
| `CueEditing` | Domain | 핫큐 누름/지우기·메모리 큐 한도·옮기기·박 이동·루프 설정·활성 루프 하나만 | 순수 |
| `LoopRules` | Domain | 즉석 루프 끝 계산(박/분수 박), ½·×2 사다리, 반복 중 저장 | 순수 |
| `GridEditing` | Domain | GridDraft 편집 + 핫큐 따라가기(carry) | 순수 |
| `GainPolicy` | Domain | 적용 게인·rekordbox 값과 잰 값 비교·제안 | 순수 |
| `TransportController` | Features | 재생·CUE(CDJ 방식)·시킹·스크럽·루프 걸기/나가기 | 가짜 `DeckAudioEngine`·`Clock` |
| `TrackLoader` | Features | 곡 로드·조용한 다시 읽기(softReload)·초안/그리드/아트워크 읽기 | 가짜 `DraftRepository` |
| `AnalysisCoordinator` | Features | 파형·섹션·조성·그리드 제안 작업(취소·캐시) | 가짜 분석기 |
| `DeckModel` | Features | 위를 조립한 화면 모델(관찰 속성만) | 통합 테스트 몇 개 |

- 설정(`DeckSettings`·무시한 제안 목록)은 `SettingsStore`, 초안 저장은 `DraftRepository`, 아트워크는 `ArtworkProvider`로 옮긴다.

## 5. 함께 넣을 안전장치 (조사 결과 반영)

- **rekordbox 버전 허용 목록 + 스키마 지문**
  - rekordbox 앱 버전(`Info.plist`)과 `PRAGMA table_info` 지문, `djmdProperty.DBVersion`을 확인한다.
  - 모르는 버전·스키마면 쓰기를 막고 읽기 전용으로 둔다.
  - 4단계 `WriteGuard`에서 테스트 먼저 만든다.
- **`agentRegistry.lastUpdateCount`(클라우드 최대 USN) 확인**: 로컬 카운터가 이보다 낮으면 쓰지 않는다.

## 6. 하지 않는 것 / 결정이 필요한 것

- 기능 추가는 이 계획이 끝날 때까지 미룬다. 단, 버그 수정은 테스트 먼저 방식으로 바로 한다.
- 결정 필요:
  1. 타깃을 4~5개로 나누는 것(빌드는 약간 복잡해지고 경계는 분명해짐) vs AnicueCore 하나 안에서 폴더만 정리.
  2. CLI에 swift-argument-parser 의존성 추가 여부.
  3. 끝난 실험 CLI 명령을 지울지, `lab`으로 남길지.
  4. 커버리지 목표(쓰기 80%, 코어 60%)가 적절한지.

# DJCrate 라이브러리 조회·제안 (djc)

`djc` 읽기 명령으로 rekordbox 라이브러리의 **스냅샷 사본**을 읽고, 고칠 것을 표로 제안한다. 고치는 일(초안 만들기·rekordbox 반영)은 사람이 DJCrate 앱에서 한다.

## 안전 규칙 (먼저 지킨다)

1. **라이브 DB를 열지 않는다.** `~/Library/Pioneer/rekordbox/master.db`, `share/PIONEER/USBANLZ`, 음원 파일을 sqlite·셸 등으로 직접 열거나 복사하지 않는다. 읽기는 아래 djc 읽기 명령으로만 한다. `--db`에 라이브 DB(링크 포함)를 주면 djc가 `live_database`로 거절한다. 우회하지 않는다.
2. **rekordbox에 쓰지 않는다.** `cue-write`, `track-add`, `track-delete`, `rekordbox-restore`, `--live`가 붙은 명령, `djc lab …`은 실행하지 않는다. 사람이 시켜도 이 스킬로는 하지 않고, DJCrate 앱에서 하라고 안내한다.
3. **제안까지만 한다.** 초안을 만드는 `djc draft …`는 준비 중이다(이슈 #49). 그전에는 초안 폴더(`cue-drafts/`, `grid-drafts/`, `tag-drafts/`, `gain-drafts.json`)의 파일을 직접 만들거나 고치지 않는다.
4. **반영은 사람이 한다.** rekordbox를 완전히 끈 뒤 DJCrate 앱의 "rekordbox에 반영"(⌘⇧E)으로 미리 보기를 확인하고 쓴다.
5. **라이브러리 정보를 밖으로 내보내지 않는다.** 스냅샷·DB 사본·백업에는 rekordbox 클라우드 토큰이 들어 있다. 복사·업로드·출력하지 않는다. 곡 목록·파일 경로·곡 수를 이슈·PR·웹 서비스에 올리지 않는다.

## 준비

- `djc` 찾기: PATH에 `djc`가 있으면 그것을, 없으면 DJCrate 저장소에서 `swift build --product djc` 후 `.build/debug/djc`를 쓴다.
- 읽기 명령은 최신 스냅샷을 읽는다. 스냅샷이 없으면 `read_failed`("스냅샷이 없습니다") 오류가 난다.
- `djc snapshot`은 라이브 DB를 읽기만 해서 사본을 뜬다(rekordbox에 쓰지 않음). 사람이 rekordbox에서 고친 뒤라면 새로 뜬다. rekordbox가 켜져 있거나 막 끈 뒤 `master.db-wal`이 남아 있으면 막힌다. 그때는 사람에게 rekordbox를 꺼 달라고 하거나 기존 스냅샷을 쓴다. `--force`는 사람이 동의할 때만 쓴다(최근 변경이 빠질 수 있다).
- 연습·시험은 사본으로 한다: `DJC_REKORDBOX_DIR=<rekordbox 폴더 사본>`, `DJC_HOME=$(mktemp -d)`. 또는 명령마다 `--db <사본.db>`.

## 명령 (모두 읽기 전용)

늘 `--json`을 붙여 기계가 읽는 출력을 받는다. `jq`로 필요한 칸만 뽑는다.

| 명령 | 하는 것 | `data` |
|---|---|---|
| `djc search <검색어> [--bpm 최소-최대] [--key 키] [--playlist ID] [--filter 필터] --json` | 곡 찾기. 검색어는 제목·아티스트·코멘트·장르 부분 일치, `''`는 전체. 조건은 모두 함께 적용 | `{tracks}` |
| `djc track <ContentID> --json` | 곡 하나의 태그·큐·그리드·게인·소속 재생 목록·초안 여부 | `{track, cues, grid, gain?, playlists, drafts}` |
| `djc playlists [--tree] --json` | 재생 목록·폴더 | `{playlists}` |
| `djc playlist <ID> --json` | 재생 목록 곡을 순서대로(폴더면 하위 목록을 합침) | `{playlist, tracks}` |
| `djc drafts --json` | 반영 대기 초안이 있는 곡과 종류(cue·grid·gain·tag) | `{drafts}` |
| `djc report [--files] --json` | 라이브러리 현황 집계(코멘트 분류·큐 유무·확장자 등, `--files`면 없는 파일 수) | 집계 칸 |
| `djc parse "<코멘트>" --json` | 코멘트가 규칙(`TVA 작품명 OP 1` 꼴)에 맞는지 판정 | `{classification, parsed?}` |
| `djc path <제목> --json` | 제목으로 파일 경로 찾기(대소문자 구분) | `{paths}` |
| `djc compat --json` | rekordbox 버전·DB 구조가 쓰기를 확인한 모양인지 | 버전·카운터 |

`--filter` 이름:

| 이름 | 조건 |
|---|---|
| `no-cues` | 자동 큐를 포함해 큐가 하나도 없음 |
| `empty-comment` | 빈 코멘트 |
| `off-convention` | 규칙 밖 코멘트(구형·잔재·크레딧·기타) |
| `backlog` | 2025~2026년에 추가한 로컬 곡 중 빈 코멘트 |
| `no-bpm` | BPM이 없는 로컬 곡 |
| `tempo-change` | 그리드에 변속이 있음 |
| `played` · `streaming` · `all` | 재생 이력 있음 · 스트리밍 곡 · 전체(기본) |

JSON 약속(자세한 칸은 저장소의 `docs/cli.md`):

- 성공: 종료 코드 0, stdout에 `{"schemaVersion":1,"command":…,"data":{…}}` 한 문서.
- 실패: 종료 코드 1, stdout은 비고 stderr에 `{"error":{"code":…,"message":…}}`. `code`는 `invalid_arguments`, `not_found`, `live_database`, `read_failed`. `message`에 할 일이 적혀 있다.
- ID는 모두 문자열이다. 값이 없는 선택 칸은 키가 빠진다. 모르는 키는 무시한다.
- `Track`: `id`(ContentID), `title`, `artist`, `genre`, `comment`, `bpm`, `key`, `lengthSeconds`, `path`, `importedOn` 등.
- `Cue`: `kind`(0 메모리, 그 밖은 핫큐 슬롯), `hotCueSlot`(A~H), `inMsec`, `isLoop`, `isAutoGenerated`. `Grid`: `status`, `beatCount`, `segments`, `tempoChanges`.

## 예시 흐름

아래 ID·제목·값은 모두 합성 예다. 실제 라이브러리의 곡을 예시로 옮겨 적지 않는다.

### 1. 조건으로 곡 찾기

"125~130 BPM, 8A 곡" 같은 요청:

```sh
djc search '' --bpm 125-130 --key 8A --json \
  | jq -r '.data.tracks[] | [.id, .title, .artist // "", .bpm, .key] | @tsv'
# 101	시험 Alpha	합성 아티스트	128	8A
```

- 키 표기는 라이브러리 값 그대로 비교한다(대소문자만 무시). 먼저 결과의 `key` 값이 `8A`(Camelot)인지 `Am`인지 보고 같은 표기로 준다.
- 범위를 좁히려면 `--playlist <ID>`(ID는 `djc playlists --tree --json`에서), 말로 찾으려면 검색어를 준다.

### 2. 큐 없는 곡 찾기

```sh
djc search '' --filter no-cues --json | jq -r '.data.tracks[] | [.id, .title] | @tsv'
djc search '' --filter no-cues --playlist p1 --json   # 한 재생 목록 안에서만
djc drafts --json                                      # 이미 반영 대기인 곡은 빼고 제안
```

- 곡이 많으면 재생 목록·최근 추가(`importedOn`)·재생 이력(`--filter played` 결과와 겹치는 곡) 순으로 우선순위를 매겨 보여 준다.
- 제안: "DJCrate 앱에서 곡을 열어 메모리 큐 후보(곡 구조 분석)를 확인하고 찍으세요."

### 3. 코멘트·태그 정리 제안

```sh
djc report --json | jq '.data.commentClasses'          # convention·legacy·residue·credit·empty·other 개수
djc search '' --filter off-convention --json | jq -r '.data.tracks[] | [.id, .title, .comment] | @tsv'
djc parse "TVA 시험 OP 1" --json | jq -r '.data.classification'   # 제안한 코멘트가 규칙에 맞는지 → convention
```

- 코멘트 규칙은 이 라이브러리 주인의 규칙이다. 사람이 원할 때만 규칙에 맞추는 제안을 하고, 제안값은 `djc parse`로 `convention`이 나오는지 확인한 뒤 보여 준다.
- 태그는 `search` 결과에서 같은 아티스트·장르의 표기 흔들림(대소문자·띄어쓰기·전각), 빈 장르·앨범을 찾는다. 곡 하나의 전체 태그는 `djc track <ID> --json`.
- 제안 표: `ContentID | 제목 | 칸 | 지금 값 → 제안 값 | 이유`. 칸 이름은 앱과 같게(제목·아티스트·앨범·앨범 아티스트·장르·작곡가·연도·트랙 번호·코멘트).
- 적용: 사람이 DJCrate 앱의 태그 편집(⌘I)이나 태그 시트에서 초안으로 만들고 반영한다. `djc draft tag …`는 준비 중(#49).

### 4. 세트용 곡 후보 뽑기

"126 BPM에서 시작해 132까지 올리는 30분 세트" 같은 요청:

```sh
djc playlists --tree --json | jq -r '.. | objects | select(.id? and .name?) | [.id, .name, .trackCount] | @tsv'
djc search '' --playlist f1 --bpm 124-134 --json \
  | jq -r '.data.tracks[] | [.id, .title, .bpm, .key, .lengthSeconds] | @tsv'
djc track 101 --json | jq '{cues: (.data.cues | length), tempo: .data.grid.tempoChanges, gain: .data.gain.decibels}'
```

- 후보마다 `track`으로 큐가 있는지(없으면 믹스 지점을 잡기 어렵다), 변속(`tempoChanges`)이 있는지, 게인이 튀는지 본다.
- 순서는 BPM을 조금씩 옮기고, 키는 Camelot 이웃(같은 숫자의 A↔B, 같은 글자의 숫자 ±1)으로 잇는다. `lengthSeconds`를 더해 목표 길이에 맞춘다.
- 제안 표: `순번 | ContentID | 제목 | BPM | 키 | 이음 이유`. 재생 목록으로 만드는 일은 사람이 한다(재생 목록 초안은 준비 중).

## 제안을 보여 줄 때

- 곡마다 ContentID와 제목을 함께 적는다(사람이 앱에서 찾을 수 있게).
- 바꿀 값은 "지금 값 → 제안 값"과 이유 한 줄로 쓴다. 확실하지 않으면 그렇다고 적는다.
- 끝에 "반영은 DJCrate 앱에서 초안으로 만든 뒤, rekordbox를 끄고 'rekordbox에 반영'(⌘⇧E)으로 하세요"를 한 줄 붙인다.

## 문제 해결

| 오류 | 할 일 |
|---|---|
| `live_database` | `--db`에서 라이브 경로를 빼고 스냅샷을 읽는다 |
| `read_failed` "스냅샷이 없습니다" | `djc snapshot`(rekordbox가 켜져 있으면 사람에게 먼저 묻는다) |
| `not_found` | `djc search`로 ContentID, `djc playlists`로 재생 목록 ID를 확인한다 |
| `invalid_arguments` | 인자 없이 `djc`를 실행해 사용법을 본다 |
